## Source 1

Title: What to look for in a code review

Author / Organization: Google

Publication date: Living documentation

Version: Current documentation

URL: https://google.github.io/eng-practices/review/reviewer/looking-for.html

Source type: official docs

What it establishes:
Review should consider design, functionality, complexity, tests, naming, comments, style, documentation, and context.

What this skill adopts:
Review intent and correctness first; each finding needs location, evidence, consequence, and fix direction.

What it does NOT establish:
It does not establish universal severity labels or justify style-only blockers.

Numbers taken from source:
No numerical threshold is adopted.

Reverify when:
The review standard or repository conventions change.
